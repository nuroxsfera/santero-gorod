# Geography v1.0 — зафиксированный клиентский фундамент

**Статус:** frozen client foundation  
**Дата фиксации:** 2026-10-15  
**Коммит-ориентир:** main (после интеграции CitySearchScreen)

## Назначение

Единый географический модуль Santero Город для выбора города, стабильных идентификаторов и привязки контента (новости, вакансии, недвижимость и др.).

## Публичный контракт

```ts
import {
  getGeographicService,
  getCityContext,
  toGeographicReference,
  type Locality,
  type GeographicReference,
  CitySearchScreen,
} from "@/geography";
```

### Стабильные идентификаторы

- `Locality.id` — основной ID (GUID-подобная строка; предпочтительно FIAS, когда доступен).
- `GeographicReference.localityId` — то, что **должны** хранить другие модули.
- Не хранить только название города: названия дублируются между регионами.

### Выбор и восстановление города

1. `getGeographicService().ensureLoaded()` — каталог (fetch catalog.json → fallback seed).
2. `getCityContext().hydrate()` — чтение `localStorage`.
3. `getCityContext().selectLocality(locality)` — запись выбранного города + recent.
4. Смена города не должна затирать независимые пользовательские данные других модулей (ключ контекста только географический).

### Как ссылаться из других модулей

```ts
const ref = toGeographicReference(locality);
// ref.localityId, ref.regionId, ref.countryCode
```

Уровни привязки контента:

| Уровень | Поля |
|---------|------|
| Населённый пункт | `localityId` |
| Регион | `regionId` |
| Федеральный | `countryCode: "RU"` без locality/region |

## Данные

| Слой | Содержание |
|------|------------|
| `src/geography/data/seed.ts` | ~20 крупных городов, всегда в бандле |
| `public/data/geography/catalog.json` | Расширенный клиентский набор |
| Источник исходных данных | epogrebnyak/ru-cities (официальные **города**) |

Офлайн ранее проверялся полный набор **1117** городов; в репозитории — урезанная public-версия + seed. Это **не** полный ГАР.

## Известные ограничения (tech debt)

1. Backend / PostgreSQL / `PostgresGeographicRepository` — не реализованы.
2. Импортёр ГАР — отсутствует.
3. Полный каталог 1117 не лежит целиком в git (лимиты артефакта).
4. Vitest / lint / tsc / `next build` в CI-окружении агента **не подтверждены** успешным прогоном.
5. Полнота и лицензионные условия источника требуют отдельной юридической проверки для production.

## Путь к серверу

1. Реализовать `GeographicRepository` на PostgreSQL.
2. Импорт ГАР с upsert по FIAS GUID.
3. API `/api/v1/geo/*`.
4. Клиентский `GeographicService` без смены публичного контракта.

**Правило:** не расширять Geography без блокирующей причины для других модулей. Следующий модуль — Новости.
